# Parquet logical schema registry

`market-contracts` owns the registered logical schemas in `schemas/fixtures/parquet-schema-registry.json`; the same registry is packaged in the Python contracts wheel. The canonical descriptor has `schema_version`, `schema_id`, and an ordered `fields` list. Object keys are serialized lexically, field order is preserved, JSON is compact UTF-8 with non-ASCII characters unescaped, and the fingerprint is:

```text
SHA256(UTF8("LQEpoch-Parquet-Schema-v1\n") || canonical_descriptor_json)
```

Rust, Python, and TypeScript tests compute the same canonical bytes and compare the shared golden hashes. A matching descriptor hash identifies logical shape only; it does not prove that a file's actual Arrow schema, rows, completeness, provenance, entitlement, or contents are truthful. Storage readers must compare the actual physical schema to the trusted descriptor and independently hash the bytes they read.

| Logical type | Arrow physical type | Parquet physical/logical type | Row constraint |
| --- | --- | --- | --- |
| `utf8` | `Utf8` | `BYTE_ARRAY (STRING)` | Valid UTF-8 text; source identity and enum constraints apply at the owning DTO. |
| `uint32` | `UInt32` | `INT32 (UINT_32)` | Integer in `[0, 2^32-1]`. |
| `uint64` | `UInt64` | `INT64 (UINT_64)` | Integer in `[0, 2^64-1]`; JSON and ProtoJSON use canonical decimal strings, never JavaScript `number`. |
| `timestamp_ns_utc` | `Timestamp(Nanosecond, UTC)` | `INT64 (TIMESTAMP(isAdjustedToUTC=true, unit=NANOS))` | UTC epoch nanoseconds must fit signed `i64`; reject out-of-range timestamps and never truncate. |
| `date_iso8601` | `Utf8` | `BYTE_ARRAY (STRING)` | Exactly `YYYY-MM-DD`, a valid Gregorian date. |
| `decimal_string` | `Utf8` | `BYTE_ARRAY (STRING)` | Exact bounded base-10 value as provided by `DecimalString`; no binary-float conversion in storage. Field-specific price/size sign rules still apply. |
| `sha256_hex` | `Utf8` | `BYTE_ARRAY (STRING)` | Exactly 64 lowercase hexadecimal characters. This format does not establish hash truth. |
| `bool` | `Boolean` | `BOOLEAN` | Boolean value. |
| `binary` | `Binary` | `BYTE_ARRAY` | Exact bytes; row consumers enforce the 1 MiB raw-frame bound before hashing or decode. |

Unknown schema IDs, fields, and logical types are rejected. The current event and bar descriptors for each registered storage revision are represented in the single cross-language registry and tests; a field order, type-width, or nullability change alters the hash and requires an explicit schema version review.

`lqepoch.market_event.v1` stores normalized event rows. `numeric_encoding` identifies the source value representation. When a binary float is shortest-decimal projected, `raw_frame_sha256` is required per event; the projection is not source-exact and remains unqualified absent independent tick evidence. `decimal_token` REST inputs must preserve the original JSON number token with arbitrary-precision parsing.

`lqepoch.market_raw_frame.v1` stores exact received MessagePack market-data frames; `lqepoch.market_raw_json_frame.v1` stores the same bounded row contract for exact JSON application-frame bytes. Their SHA-256 is recomputed from `frame_bytes`; each uncompressed frame is capped at 1 MiB and its expected normalized event count at 512. JSON capture preserves malformed application frames as bytes for bounded quarantine and does not require successful JSON parsing. `symbols_json` is compact UTF-8 JSON of that frame's lexically sorted, unique normalized market symbols, capped at 512 entries and 263,681 bytes before parsing. Each positive expected event count requires at least one known symbol and cannot be smaller than the number of distinct symbols. Control rows must have zero expected market events and an empty symbol list. Unknown, malformed, or provider-error frames retain any known expected market-event count and decoded-symbol evidence. A single diagnostic/control frame may have an empty symbol list, but a formal dataset may be published only when the full batch symbol union is non-empty. Dataset manifests mark these objects with their distinct `raw_messagepack_bytes` or `raw_json_bytes` encoding and matching trusted schema fingerprint; both markers are rejected in normalized market events and predictions. Adding the raw JSON enum variant is additive on the wire but source-breaking for Rust exhaustive matches; consumers must pin-upgrade and rerun contract checks, while existing frozen pins remain unchanged. Raw-frame manifests require `time_range` to be absent and `source_timestamp_missing_rows` to equal `row_count`. `source_numeric_encoding` on a raw row is optional and describes only a uniform projection of the frame's numeric fields. Neither raw-frame schema has a source timestamp, so its manifest uses no time range and marks every row as missing a source timestamp.

`lqepoch.market_event.v2` is a storage-descriptor revision that appends nullable raw-frame correlation fields to the v1 event columns; it does not change `MarketEventEnvelopeV1`. Its existing `schema_version` column therefore retains the wire event value `1`. The four correlation columns are all present or all absent. When present, the event's raw-frame SHA is required, the raw generation equals the event generation, frame sequence is positive, and the 1-based ordinal is within the declared expected event count (at most 512). The expected count is not the count of events successfully delivered; downstream completeness checks must reject a missing projection rather than silently qualifying the raw frame. Generation scope and durability are owned by the adapter; these schemas do not assert that a generation is unique across process restarts.

The additive capture-scoped descriptors are `lqepoch.market_raw_frame.v2` (`85ad0ee5a29ce165a48f459fae6d85c58a12a5c4ed387f6844884af1ef0351ea`), `lqepoch.market_raw_json_frame.v2` (`bbb0b248a36a820a3587793ff4da41dc3e3e5852a75ce1b05401b45d3245385e`), and `lqepoch.market_event.v3` (`2df41366161a20007593a5f1dc908acb9e593c06f3d1d54b68a10a1baf7291fb`). The V1 raw descriptors and `market_event.v2` remain byte-for-byte unchanged; consumers must select the descriptor explicitly and must not silently upcast old rows. Raw V2 rows keep `schema_version=2` and add the opaque lowercase UUIDv4/RFC-variant `capture_instance_id`, `source_generation`, `source_frame_sequence`, and post-decode `canonical_generation`. Their ordered columns are `schema_version, provider, feed, entitlement, source_numeric_encoding, capture_instance_id, source_generation, source_frame_sequence, canonical_generation, received_timestamp_utc, frame_sha256, frame_bytes, event_count, disposition, symbols_json`; their types and nullability are in the trusted registry. The UUID is a join identity, never a filesystem path. The source generation belongs to the pre-decode capture key; canonical generation comes from the post-decode projector and must match the event generation.

Raw V2 and Event V3 timestamps must originate from an exact UTC lexeme with uppercase `T`, zero offset, no leap second, at most nine fractional digits, and a value representable by signed Arrow `i64` nanoseconds. The Rust `UtcTimestamp::parse_for_arrow_nanoseconds` entry point enforces this directly. The legacy `UtcTimestamp::parse` keeps its prior normalization behavior for V1 and records only a boolean indicating whether the original in-memory lexeme met the V2 requirements; it does not retain a second copy of the input string. The marker is excluded from V1 equality, ordering, hashing, debug output, and serialization, which continue to use the parsed instant and canonical text. A V2/V3 validator can therefore reject a lossy or out-of-range parse before serialization, but callers upgrading a legacy timestamp must parse the original source lexeme and must not treat a previously canonicalized V1 string as proof of its original precision.

Raw V2/V3 symbol validation rejects strings containing unpaired UTF-16 surrogate code points. JavaScript `JSON.parse` and Python's JSON decoder can represent such escaped values, while Rust strings require valid Unicode scalar values. Before encoding `symbols_json`, Python checks its code-point length and TypeScript checks its UTF-16 code-unit length against the byte cap; both counts are lower bounds on UTF-8 size for valid scalar text. They then reject invalid scalars and compute the bounded UTF-8 length before JSON parsing. The same length lower-bound check precedes UTF-8 encoding for provider, feed, source-record, and normalized-symbol identities at their 128-byte or 256-byte limits. This prevents oversized identity input from allocating an unbounded encoded copy, and TypeScript never lets `TextEncoder` replacement-encode an actual lone surrogate. Python validators return a normal validation failure instead of leaking `UnicodeEncodeError`. The 16 MiB aggregate `symbols_json` limit counts the encoded UTF-8 bytes of each row's exact string in Rust, Python, and TypeScript.

Event V3 appends nullable `raw_frame_capture_instance_id` and `raw_frame_source_generation` to every Event V2 column. All six correlation fields across V2 and V3 must be present together or absent together. When present, rows bind the exact frame SHA, UUID, source generation, source frame sequence, canonical generation, receive timestamp, provider/feed/entitlement, expected event count, ordinal, projection encoding when supplied, and a symbol present in the frame's sorted symbol list. A chunk validator requires one capture UUID and one source generation, at most 1,024 full frames, 16 MiB total raw bytes, 16 MiB aggregate `symbols_json` bytes, contiguous source-frame sequences, and all expected normalized event ordinals. It parses each frame's bounded symbol list once per chunk and reuses that result for its event rows. The chunk helper may validate a continuation chunk; the MDP capture-level receipt must additionally prove each generation begins at sequence 1 and every chunk boundary is contiguous. This checks row-to-row structure; it does not prove the private spool is durable, validate a publisher receipt, confer provider authority, or qualify source completeness. MDP owns its pair/publication receipts and must verify storage readback before any downstream admission. Rust `market-contracts` is the authority for full market-event semantic validation, including source encoding/hash rules, exact event-specific value constraints, and OCC candidate syntax. The installed Python wheel and TypeScript provide bounded row-shape and raw/event pairing checks; they do not establish full Rust semantic equivalence or replace Rust validation at the admission boundary. The shared fixtures contain only synthetic test bytes.

The installed Python package includes this same generated registry as a wheel resource. Consumers should call `load_trusted_parquet_schema_registry`, `trusted_parquet_schema_descriptor`, or `trusted_parquet_schema_sha256` rather than copying the descriptors. Install the locked optional `arrow` extra to use `verify_pyarrow_schema`; the helper compares actual ordered field names, physical types, timestamp units/timezones, and nullability to the trusted descriptor. It does not hash data or verify row completeness.

New Arrow writers should attach `lqepoch.schema_descriptor.v1` (the exact canonical descriptor UTF-8 JSON) and `lqepoch.schema_fingerprint_sha256` (the exact lowercase SHA-256) to the Arrow schema metadata and flat Parquet footer. These metadata values are excluded from the logical fingerprint. Older files with neither registry key remain readable after registry and physical-schema verification, even if they contain unrelated Arrow metadata. If either registry key is present, both must be present with exact registry values; unrelated keys may coexist. `market_contracts::trusted_parquet_schema_metadata` provides the writer values, and `validate_optional_parquet_schema_metadata` checks reader metadata without requiring an Arrow dependency in core.

`lqepoch.us_equity_trade_bar_1m.v1` is a separate trade-only minute-bar schema. Quote and option events do not become OHLCV rows. Session and window identity must be explicit. Research consumers must not treat event Parquet as minute features or infer session calendars from timestamps.

`lqepoch.us_equity_trade_bar_1m.v2` is additive and leaves the V1 descriptor and fingerprint unchanged. It preserves the ordered V1 fields and appends required `completion_evidence_sha256` as lowercase SHA-256 text; the registered descriptor fingerprint is `5e9df2f97ec1786bcb1037cba82d8721ca87d12b96789808ba2a95b0f1605d54`. The Parquet descriptor registry version remains `1`; the row's `schema_version` value is `2`. The hash references the canonical ProtoJSON bytes of the unique `DatasetManifestV2.completion_evidence` oneof. Rust, Python, and TypeScript expose row-to-manifest validation that checks source identity, symbol membership, source-time bounds, completion mode, finite EOF/page-presence projection, and the evidence digest. Each row's source-time half-open range must be contained by its own bar interval and by the manifest range. The bar duration is exactly 60 seconds; the contract does not infer UTC minute-boundary alignment. The row repeats selected manifest evidence for query convenience, but the immutable manifest hash remains the dataset identity and consumers must validate the manifest and actual Parquet rows. A matching row digest does not prove receipt issuer authenticity, provider completeness, entitlement, or research qualification. The current MDP HTTP service remains on BarV1; this contract does not add a producer, endpoint, or automatic migration.
