# Market bars query V1

`market-contracts` defines the shared wire DTO for the consumer-facing `GET /v1/market/bars` contract. It does not implement an HTTP server, provider client, cache, calendar, or entitlement check. The canonical snake_case query and response shapes are in `proto/lqepoch/market/v1/bars.proto`, `schemas/openapi.json`, and `schemas/fixtures/market-bars-v1.json`.

The shared fixtures contain synthetic compatibility data. `market-bars-v1.json` uses `provider: synthetic`, `feed: fixture`; `market-bars-v1-unknown-feed.json` simulates an Alpaca observation whose actual feed and entitlement are unknown, with a provisional row. Neither fixture is evidence of an external provider connection, SIP identity, entitlement, or source authority. A consumer must preserve an unknown feed instead of inferring one from the requested provider mode.

The query requires `symbol`, `asset_class`, `start`, `end`, `resolution`, `session_scope`, `adjustment`, `provider_mode`, `allow_daily_downgrade`, and `limit`; `cursor` is optional. `start` is inclusive and `end` exclusive UTC RFC3339. `limit` is 1 through 1000. A non-daily request can return daily bars only when the caller explicitly permits downgrade.

The response echoes the requested resolution and adjustment, identifies the effective resolution, and carries exact decimal-string OHLCV rows. Every row has an event window, collector `received_at_utc`, normalized `available_at_utc`, `provenance_id`, `session_instance_id`, `resolution`, `adjustment`, and a producer-reported `validation_state`. `source_provenance` records the actual `provider`, `feed`, `source`, entitlement observation, and numeric encoding; numeric encoding is `decimal_token`, `integer_token`, `binary_float64_shortest_decimal`, or `binary_float32_shortest_decimal`. Top-level provider/feed/entitlement fields are summaries and must not replace per-source identity. `as_of` is the source observation cutoff when the source supplies one, and may be omitted or null when unknown; `fetched_at` is the required local fetch completion time and must never be substituted for `as_of`. `verified_at` is an independent verification timestamp. A validation state or entitlement label does not prove its producer or source is trusted.

Coverage is reported with `coverage_status`, source-backed `segments`, and explicit `gaps[].reason_code`. A gap may be returned without a session segment when calendar identity is unknown; producers must avoid describing closed-market time as a data-coverage gap. A gap may overlap a partial or unknown segment, but cannot overlap a complete segment or any returned bar interval. Supported statuses include `complete`, `partial`, `empty`, `unknown`, and `unsupported`. `cache_status` includes `unavailable` and `unknown`; `market_calendar_version` is optional. A truncated response must include `continuation_cursor` and cannot claim complete coverage. Consumers must continue paging before treating a bounded result as complete.

Rust exposes the bounded semantic entry points `BarsRequestV1::parse_json`, `BarsResponseV1::parse_json`, and `BarsRequestV1::validate_response`. The validator checks exact decimal OHLCV ordering, positive OHLC values, non-negative volume, half-open positive intervals, receipt/availability ordering, row adjustment and requested instrument/resolution consistency, source references, session association, response summaries, and pagination consistency. It deliberately does not assume a fixed duration for hourly or daily bars because exchange calendars and daylight-saving changes determine those windows.

The checked-in Python and TypeScript Protobuf bindings provide generated structural compatibility and are tested against the same golden JSON fixture. They do not provide the Rust semantic validator. Until a consumer runs the Rust validator or implements equivalent reviewed checks, decoded `validation_state`, `verified_at`, `authorized`, and provider labels remain untrusted source assertions and cannot promote rows for research or execution. The market-read bearer delegation is separate from this DTO: it is an HS256 token with a maximum 60-second lifetime and `market:read` scope; this crate does not issue or verify it.
